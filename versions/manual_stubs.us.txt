# Not COP0. Functions N64Recomp cannot translate for a structural reason, one
# per line. Merged into the `stubs` block by cop0_stubs.py.
#
# All 48 below are one class: a routine that reads a jump table in
# code_rodata_tail which a second routine, in the other VM module, reads too.
# Every one of the 49 duplicated table reads in the ELF is split across the two
# modules -- none is internal to either -- and the table's entries name the
# case bodies of the copy in `virtual` (below 0x43C000). For the copy in
# `virtual_1` they all fall outside its own body, so N64Recomp reports
#
#     Failed to determine size of jump table at 0x800C1438
#
# and stops.
#
# The likely reason is that the VM loader relocates these tables when it pages
# a module in: a table of absolute code addresses cannot be shared by two
# modules that live at different addresses unless someone rewrites it. That is
# what VMASM.S / VMEMORY.C are for. A static recompiler cannot follow a table
# that is rewritten at load time, so these need the runtime to supply the
# behaviour -- the same answer the TLB itself gets.
#
# Stubbing loses the `virtual_1` copy. Its twin in `virtual` is translated
# normally, so the code exists in the output; what is missing is the entry
# point at the second address. Revisit once the VM loader is understood well
# enough to say which copy actually runs. See #40.

# Second class, same root as the first. These call an address that no symbol
# can be placed at: it is either a branch's delay slot or inside a function
# whose own branches cross it, so seeding it splits that function and the
# recompiler rejects the pieces with "Unhandled branch".
#
# N64Recomp handles exactly this case on its own when caller and callee share a
# section -- resolve_jal returns CreateStatic and emits a static function at the
# address. It declines across sections, and says why: "A static can't be created
# as the target section is unknown", because with overlays one vram can belong
# to several sections. The static is also registered under the *caller's*
# section index, which is the wrong home for a cross-section target, so lifting
# the restriction is not a one-line change.
#
# 215 engine functions are in the same situation and need nothing, because their
# calls stay inside `code` and CreateStatic covers them. Only these, calling out

// Data names, part g7: every D_ symbol not in 0x80xxxxxx: D_002xxxxx (engine segment), D_0042xxxx-D_0043xxxx
// (VM module-1 data) and D_0046xxxx, plus module-2 copies (`_2`). Addresses are the D_ token's own address:
// module-2 code refers to its data by LINK address, which sits 0xE0 below the module-1 original in this
// range (D_00430E30 = D_00430F10 - 0xE0, ...), a `_2` line is at the NAMED address (link + 0x39000) like every module-2 name;
// the coordinator converted g7's link addresses (round G2) and notes the link address on each line.
// Module-1 data is ROM = vaddr - 0x2B6000; module-2 data ROM = link + 0x39000 - 0x2B6000 (checked byte for byte).
// `s` = file-local data of one boss/menu source file; `g` = referenced across subsystems (menu descs the engine opens).
// A D_ pointing inside an object is gObject_<field> (coordinator convention).

// Names for 0x00260000-0x0026FFFF (round N2, part n4).
//
// Most of this range is the engine's per-intelligence-type AI code. Its
// tables tell what each function is: D_800ACB60[m_Type] (indexed by
// CIntelligence::m_Type, the INTELLIGENCE_* enum of structs/intelligence.h)
// gives each type a {setup, advance, then {onActor, onEvent} event-handler
// pairs} block (D_800B2628[kind] points 8 bytes into it: the handlers
// func_0026DFB0 runs for a level event); the setup installs a CAIModeInfo
// table whose rows give each mode's enter/update callbacks. The enemy's
// block (D_800B1760) has instead D_800B1790[behaviour], one
// CEnemyBehaviorInfo {m_SetupFunction, m_AdvanceFunction,
// m_pGroundModeTable, m_pAirModeTable, m_pUnderwaterModeTable} per
// behaviour value (struct and field names from the ROM's SN64 debug type
// records at ROM 0x14E443). Mode numbers are named from the same debug
// records: the EnemyModes, DoorModes, ActionModes, DestructibleModes and
// ThrowableModes enums (ROM 0x14E592-0x14F21D, each member preceded by its
// value), e.g. 0x04 ENEMY_MOVE_MODE, 0x0A ENEMY_IDLE_MODE, 0x0E
// ENEMY_ATTACK_COMBAT_MODE, 0x10 ENEMY_ATTACK_DART_MODE, 0x17
// ENEMY_TELEPORT_OUT_MODE, 0x1B ENEMY_PUFFUP_MODE, 0x31/0x32
// ENEMY_JOYPAD_TEST_IDLE/PLAY_ANIM_MODE, 0x3D ENEMY_NUKED_FROZEN_MODE.
// "Event" handlers below are the {onActor, onEvent} pairs: onActor runs on
// the actor when it is in the current level, onEvent (the *Remote names)
// only records the change in the saved-actor bits of the other level
// (func_002245BC). Handler numbers are the LevelEvent.handler index.

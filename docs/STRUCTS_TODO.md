# Structs to hoist

The readability pass (see docs/MATCHING.md, "The readability pass") named the
fields of 1,140 matched files, but where no header fit yet each file defined
its own local struct. The same object was described many times over, under
different names and with different subsets of fields. The struct
consolidation (below) moved the biggest families into `include/structs/`;
this file keeps what is done, what stayed local and why, and what to merge
next.

The tables at the end are generated by `tools/struct_census.py` from
`src/us/code/*.c` (every top-level `typedef struct/union ... Name;`, grouped
by name). "Layouts" counts the different bodies a name has, so a name with
many layouts is usually one object seen through different subsets of fields
(CAI, Actor), but can also be a generic name reused for unrelated things
(State, Arg0, Entry, Obj): check the offsets before merging. Pairs like
func_00413230 / func_0044C230 are the two copies of a VM module and will
always repeat.

Before the consolidation the census counted 720 local names defined in 2 or
more files, out of 1,704 (the first version of this file, by a slightly
different scan, said 717 of 1,699); after the first pass, 612 of 1,557;
after the second, 534 of 1,416. The vector, intelligence, libultra, Gfx,
sound, AI state (CAI, AI, Targets), controller, game, weapon, pak, list,
cache and boss copies are gone; most of what is left is per-function
scratch structs (Obj, Arg0, Sweep, Quad, Slot, State, Timer), the actor
views that are not a CGameObjectInstance (particles, the 0x198 static
object), the CPlayer/owner views a file keeps for its codegen, and the
VM menus' item views (O01*, O06A).

## The struct consolidation (done)

Seven families, each done in its own branch and merged with every function
still matching (`make verify` passes). The shared headers and what each
holds are listed in docs/MATCHING.md, "Shared headers".

- **Vectors** (`structs/vector.h`: CVector3, CQuaternion, CMtxF, included by
  game_object.h). Vec3f/Vec3/V3/Point3/M04Vec3/B19Vec3/Quat/Quatf/Quat4 are
  gone from src/us/code except where a file takes Vec3 from
  `include/rw/abu_types.h` (imported Rage Wars code, left alone). V3 (s32
  fields) was only ever copied or passed by value, so CVector3 compiles the

  0x290, as the world's object lists (D_8010FEB4 active, D_8010FEA0 free)

## include/structs/player.h (fixed and hoisted)

against the code: CPlayerLoadSaveData is 0x4E8 (no m_dwLevelMissionObjFlags;
the nuke parts start at 0x4DC), CPlayer has no unk_0xA2C and no

The local Player,

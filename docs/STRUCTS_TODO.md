# Structs to hoist

The readability pass (see docs/MATCHING.md, "The readability pass") named the
fields of 1,140 matched files, but where no header fit yet each file defined
its own local struct. The same object was described many times over, under
different names and with different subsets of fields. The struct
consolidation (below) moved the biggest families into `include/structs/`;
this file keeps what is done, what stayed local and why, and what to merge
next.

The tables at the end are generated by `tools/struct_census.py` from
every game C file (`tools/srcfiles.py`: `src/us/{code,vm1,vm2}/<module>/`, `src/port_libultra`; every top-level `typedef struct/union ... Name;`, grouped
by name). "Layouts" counts the different bodies a name has, so a name with
many layouts is usually one object seen through different subsets of fields
(CAI, Actor), but can also be a generic name reused for unrelated things
(State, Arg0, Entry, Obj): check the offsets before merging. Pairs like
func_00413230 / func_0044C230 are the two copies of a VM module and will
always repeat.

Before the consolidation the census counted 720 local names defined in 2 or
more files, out of 1,704 (the first version of this file, by a slightly
different scan, said 717 of 1,699); after the first pass, 612 of 1,557;
after the second, 534 of 1,416; after the third, 431 of 1,192; after the
fourth, 291 of 1,013; after round L, 229 of 889 (228 of 863 by the census at
7340fcdd); after round 21 j3, 174 of 803; after round 22 k3, 148 of 723. The vector,
intelligence, libultra, Gfx, sound, libaudio, AI state (CAI and its
var-buffer views), controller, game and engine, weapon, pak, list, cache,
boss, particle, collision, save, demo, pager, menu, player / owner /
camera, level actor, model, light, pick and table copies are gone; most of
what is left is per-function scratch structs (Arg0, Tuning, Entry, State,
Slot) and the views a few files keep for their codegen (listed in each
pass below).

## The struct consolidation (done)

Seven families, each done in its own branch and merged with every function
still matching (`make verify` passes). The shared headers and what each
holds are listed in docs/MATCHING.md, "Shared headers".

- **Vectors** (`structs/vector.h`: CVector3, CQuaternion, CMtxF, included by
  game_object.h). Vec3f/Vec3/V3/Point3/M04Vec3/B19Vec3/Quat/Quatf/Quat4 are
  gone from src/us/code except where a file takes Vec3 from
  `include/rw/abu_types.h` (imported Rage Wars code, left alone). V3 (s32
  fields) was only ever copied or passed by value, so CVector3 compiles the
  same.
- **Actor** (CGameObjectInstance, `structs/game_object.h`): about 200
  files use CGameObjectInstance instead of a local Actor/LevelActor
  (m_nTypeFlag is u16: every reader uses lhu; CAnimationState's m_nFrames,
  m_bCycleCompleted and m_bAnimActive are signed: every reader uses lh/lb).
  The views 0x290 bytes long (the list link at 0x28C) are CListedInstance:
  the instance, its CList links at 0x288/0x28C and the owner counter at
  0x290, as the world's object lists (D_8010FEB4 active, D_8010FEA0 free)
  hold them. 20 files still define an Actor and 2 a LevelActor, all views
  of something else or kept on purpose: the 0x198 static object (flags u16

  func_002222E0, and func_0022D2FC's), particles (a pointer at 0x10C:
  func_002318D4..func_00232934, func_00247C10), func_00231E94 and
  func_00232044 (fields at 0x118/0x150 the instance does not have there),
  func_00246918 (an imported Rage Wars menu object),

  func_0026961C/func_00269780, func_0040F240/func_00448240 (cinema
  actors), and func_002600E8/func_00260554 (they test m_dwFlags through a
  bitfield union, which is not the code the masks give).
- **CIntelligence** (`structs/intelligence.h`, the definition
  `header.m_pIntelligence` points at; included by game_object.h, so the
  member is typed). Names from Rage Wars' debug type records, a common

- **Player** (`structs/player.h`): see the next section.
- **World and regions** (`structs/world.h`: CScene, D_800F7078, 0x19078
  bytes with its warp, sector, record and level-header types;
  `structs/region.h`: CGameRegion and CRegionInfo, the floor triangles and

  M5Grid/M04World/B18Mgr views of D_800F7078, the Triangle views and the

  WorldSector of 4 imported Rage Wars files (func_0040333C, func_004196B0,

- **Sound** (`structs/sound.h`: CAudioWorld, SndVoice, SndVoiceParams, SndEnv,
